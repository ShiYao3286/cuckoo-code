## P0 · 真机验证（**只有你能做，我无法代劳**）

> 为什么排第一：六层护栏**一次真实环境都没跑过**。单测只能证明逻辑对，证明不了模型会配合。
> 继续堆机制之前，必须先知道这些护栏是真有用还是拖慢速度。

### 验证环境

- 装 **v0.8.24 绿色版**：`cuckoo-code-win-v0.8.24-x64.zip`，解压即用
- 配置和登录态与安装版共用（`%APPDATA%\cuckoo-ai-pro-session`），不用重新登录

### 待验证项

- [ ] **V1 · 改前必读**（030/032）
  - 做法：跑一个要改多个文件的任务
  - 观察：是否出现 `[error code: NOT_OBSERVED]`；被拒后模型是**自动先 read 再重试**，还是原样重发
  - 通过标准：被拒一次后即调整，不出现连续 3 次以上相同失败

- [ ] **V2 · 长输出落盘**（032）
  - 做法：跑一个输出很长的命令（如 `npm test`、`git log`、遍历大目录）
  - 观察：是否出现「【完整输出已落盘】」，模型是否按指引去 `grep`/`read` 那个文件
  - 通过标准：不凭开头猜中间内容

- [ ] **V3 · 重复调用提醒**（033）
  - 做法：制造一个会卡住的场景（比如让它读一个不存在的路径、或反复轮询一个慢命令）
  - 观察：连续 3 次相同调用后是否出现「【重复调用提醒】」，模型是否换策略
  - 通过标准：提醒后调用签名发生变化

- [ ] **V4 · 计划只读**（034）
  - 做法：开 `/plan`，让它做一个需要改文件的任务
  - 观察：草稿期是否老实调 `todoWrite` 列计划；若它试图 `write`/`bash`，是否被 `PLAN_READ_ONLY` 拦住并转向
  - 通过标准：草稿期零副作用操作；确认后能正常执行

- [ ] **V5 · goal 多轮**（029）
  - 做法：`/goal` 设一个多轮目标
  - 观察：`<goal_round>` 续跑是否正常；被卡住时是否调 `goalBlocked` 并暂停
  - 通过标准：不会无限空转；不会反复刷同样的索要

### 回报方式（三个答案就够）

1. 有没有出现 `[error code: ...]`？出现几次？
2. 模型被拒后**调整了**还是**重复调用**？
3. 整体感觉比之前**更快**还是**更慢**？

> 有了这三个答案，我就能判断该调阈值、放松还是继续加码。

## P1 · 技术项（验证通过后再动，按价值排序）

- [ ] **T1 · 插件系统三个 bug**（我实测 DSH 工具时发现，与护栏无关，不干扰验证）
  - 位置：`src/plugins/cuckoo-plugins/loader.ts`、`src/plugins/dsh-compat/fs-service.ts`、`src/tools/core/ToolRegistry.ts`
  - 问题 1：`loader.ts:251` 传 `plugin.apply(ctx, {})`，未解析插件导出的 `Config` 默认值 → 官方工具包直接抛错
  - 问题 2：简化 `ctx.fs` 缺 `stat` → 依赖文件元信息的 DSH 工具必崩
  - 问题 3：**（安全）** 插件工具与内置工具同名时 `ToolRegistry.register` **静默覆盖** → 装同名插件能把可用工具换成不可用的
  - 建议：问题 3 改为拒绝注册或自动加前缀；前两个补实现
  - 工时：约半天

- [ ] **T2 · 每轮纪律注入的通用通道**
  - 现状：`JsRunner` 已有"拼在输出开头"的通道，但只服务规则注入；重复提醒是第二个特例
  - 目标：抽象成通用机制，让纪律从"开场白里的一次性文本"变成"每轮可见"
  - 风险：通道内容过多会挤占上下文，需要节制
  - 工时：约 1 天

- [ ] **T3 · system prompt 瘦身**
  - 现状：组装后约 16KB，其中 **66% 是 10.5KB 的 `api.d.ts`**，每轮重发
  - 方案：改成短索引 + 指向 `resources/tools/cuckoo-tools.d.ts` 的 `read`（DSH 的按需披露思路）
  - 收益：省上下文，长会话更晚触发压缩
  - 工时：半天

- [ ] **T4 · `read` 不要全量读文件**
  - 现状：`read.ts:225` 先 `readFileSync` 整个文件再切窗口；看前 100 行也要全读
  - 方案：按 offset/limit 计算字节区间流式读
  - 工时：半天

- [ ] **T5 · 台账持久化（可选）**
  - 现状：观察台账是内存态，重启后首次编辑需重新 read
  - 判断：当前行为**符合预期**，除非你经常重启打断长任务，否则不必做
